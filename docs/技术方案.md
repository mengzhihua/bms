# BMS 技术方案

BMS 是计费与结算系统。WMS、TMS、OMS 把业务单据推进来，本系统按合同费率生成应收应付、对账单、发票和收付款。IR 只读成本，不能下发指令。

## 1. 运行位置

| 场景 | 后端 | 说明 |
| --- | --- | --- |
| 单机 | `8080` | `application.yml` |
| 与控制塔同机 | `8084` | IR `ct_system` 种子 |

开放接口使用 `X-Api-Key`，控制塔种子键 `bms-open-key`。

## 2. 主链路

```text
上游单据（入库/出库/仓储/运输/增值/退货）
    → 按 source + extRef 幂等接入
    → 匹配有效合同计费
    → 对账单 → 发票 → 收付款核销
```

带 `statedAmount` 的单据不再按合同重算，按声明金额记一笔税额为 0 的费用。WMS 仓号 `WH01/WH02/WH03` 在接入时改记控制塔仓号 `WH-SH/WH-BJ/WH-GZ`。

上游推送口：

| 来源 | 接口 |
| --- | --- |
| WMS | `POST /api/open/wms/docs` |
| TMS | `POST /api/open/tms/docs` |
| OMS | `POST /api/open/oms/docs` |

## 3. 控制塔读

两条读口，都没有写指令：

| 接口 | 作用 |
| --- | --- |
| `GET /api/open/cost/records?from&to` | 按业务日返回未作废费用 |
| `GET /api/open/ir/snapshots` | 同一批费用，同时放在 `costs` 和 `dataType=COST` 的快照行里。`from` / `to` 可空 |

控制塔同步近 90 天。同一订单已有 BMS 运费时，控制塔汇总优先用这笔，不再叠加 TMS 快照运费。

## 4. 边界

BMS 不实现 `POST /api/open/ir/actions`。控制塔不能在这里挂起订单、改承运商或改费率。节约金额若来自控制塔指令上的 `expectedSaving`，那是估算，不是本系统核销后的毛利。
