## 1. 项目背景与目标

OTWB 供应链平台已有 OMS（订单）、WMS（仓储）、TMS（运输）三套业务系统，但"业务完成后该向客户收多少钱、该付承运商多少钱"一直依赖线下 Excel 对账，存在算法口径不一、重复计费、对账周期长、经营数据滞后等问题。

BMS（Billing Management System）的目标是成为平台的**计费与结算中枢**：

| 目标 | 做法 |
| --- | --- |
| 费率从 Excel 搬进合同 | 应收 AR / 应付 AP 合同 + 费率规则，支持固定、单价、阶梯、累进、首重续重 |
| 业务单据自动变成费用 | WMS/TMS/OMS 推送、CSV 导入、手工录入统一接入，幂等、自动计费 |
| 从费用走到钱 | 对账单 → 发票 → 收付款核销，全过程在同一套账上 |
| 经营数据即时可见 | 工作台 + 收入/成本/毛利、账龄、结算对象台账 |
| 向控制塔输出成本 | 只读的成本快照接口，不给第二本可改的账 |

## 3. 核心业务流程

### 3.1 主链路：单据 → 费用 → 对账 → 发票 → 收付款

```mermaid
flowchart LR
    D[业务单据<br/>source + extRef 幂等] --> R{匹配有效合同<br/>选最优费率}
    R -->|命中| F[费用明细 NEW]
    R -->|无合同/无费率| X[单据 FAILED<br/>不留部分费用]
    F --> ST[对账单 DRAFT]
    ST --> CF[CONFIRMED]
    CF --> INV[发票 ISSUED]
    CF --> PAY[收付款 → 核销]
    PAY --> SET[SETTLED]
    CF -.争议.-> DIS[DISPUTED]
```

### 3.2 状态机

| 对象 | 状态流转 |
| --- | --- |
| 业务单据 | `PENDING → BILLED / FAILED / IGNORED`，失败可重算 |
| 费用 | `NEW → STATEMENTED → SETTLED`，可 `CANCELLED` |
| 对账单 | `DRAFT → CONFIRMED → SETTLED`，可 `DISPUTED / CANCELLED`，取消释放费用 |
| 发票 | `ISSUED → CANCELLED`，开票金额不得超对账单余额 |
| 收付款 | 登记 → 核销 → 反核销，方向和结算对象必须与对账单一致 |

### 3.3 费率计算能力

| 计价模式 | 说明 | 示例 |
| --- | --- | --- |
| FIXED 固定 | 每单固定 | 订单处理费 2 元/单 |
| UNIT 单价 | 数量 × 单价 | 入库操作费 0.5 元/件 |
| TIERED 整段阶梯 | 落在哪一段按该段单价全量计 | 0~10 件 0.5，10~100 件 0.3 |
| PROGRESSIVE 分段累进 | 各段分别计价累加 | 运费 0~1kg 8 元，1~10kg 2 元/kg |
| FIRST_EXTRA 首重续重 | 首重整段收，超出乘续重单价 | 首重 1kg 12 元、续重 2 元，3.5kg = 17 元 |

计费单位覆盖单、行、件、箱、托、重量、体积、里程、托·天、方·天、件·天；每条规则可设最低/最高收费、优先级和仓库范围。同合同同费用项目只取一条最优规则：优先级高者胜出，同优先级仓库专用规则优先。

## 5. 对外接口

| 方向 | 接口 | 说明 |
| --- | --- | --- |
| 上游写入 | `POST /api/open/wms/docs` | WMS 入库/出库/仓储/增值/退货单据 |
| 上游写入 | `POST /api/open/tms/docs` | TMS 运输单据，缺 `bizType` 默认 `TRANSPORT` |
| 上游写入 | `POST /api/open/oms/docs` | OMS 订单单据 |
| 控制塔读取 | `GET /api/open/cost/records?from&to` | 按业务日返回未作废费用 |
| 控制塔读取 | `GET /api/open/ir/snapshots` | 成本快照（`dataType=COST`） |

鉴权使用 `X-Api-Key`。BMS **不实现**控制塔的写指令接口，控制塔不能在此改费率、冲销或核销。

### 6.2 代码评审中发现并修复的问题

项目全程接受自动代码评审，两轮评审共修复以下关键问题：

| 问题 | 修复 |
| --- | --- |
| 计费失败时残留部分费用可进入对账单 | 失败即删除本单自动费用，单据置 FAILED |
| 并发推送同一 `(source, extRef)` 产生重复单据 | 唯一索引 + 先查后插；升级库启动期自动迁移，存在历史重复数据时拒绝启动 |
| 并发生成对账单共享同一费用 | 逐条条件更新认领费用 |
| 开票 / 核销 / 反核销并发下余额错扣 | 行锁 + 条件更新，删除/作废 0 行即报错 |
| 已作废发票、已删除核销记录重复扣减 | 条件更新 `ISSUED→CANCELLED`，`deleteById` 检查影响行数 |
| CSV 多行字段解析错误 | 支持引号内换行、`""` 转义、BOM |
| 默认凭据与权限 | `/api/system/**` 仅 ADMIN；VIEWER 只读；显式设空口令时生成随机口令写日志 |

## 10. 小结

- 已交付一套**可运行、可部署、有测试、有文档**的计费结算系统，覆盖从业务单据到收付款核销的完整闭环。
- 与平台内 OMS/WMS/TMS **技术同构**，团队可无缝维护。
- 通过两轮代码评审加固了**并发、幂等、余额一致性**等财务系统关键点。
- 已为控制塔提供**只读成本口**，边界清晰：BMS 是唯一一本账。
